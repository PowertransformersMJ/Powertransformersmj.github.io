### L-35 · IA secundaria (análisis/narrativa) reusa los datos YA extraídos, NO re-manda el PDF
**Disparador**: análisis IA secundario sobre datos ya extraídos (narrativa F3). · **Cicatriz**: re-mandar los PDFs = visión + thinking + 1GiB + 540s para re-extraer lo que YA está en Firestore. · **Regla**: (`narrativaTendenciaIA`) mandar solo el resumen numérico compacto (`resumenTendenciaParaIA`: series {x,y} + umbral): sin visión/tool_use/thinking, `max_tokens` bajo, 120s/512MiB; extracción (cara, una vez) ≠ razonamiento sobre datos (barato, on-demand); anti-XSS: escapar + markdown-lite, nunca innerHTML del modelo.

### L-43 · No re-correr la IA (cara/lenta) para BACKFILL de campos derivables — usar el diagnóstico ya guardado
**Disparador**: poblar campos canónicos nuevos en informes viejos. · **Cicatriz**: "Reprocesar" re-extraía TODO con Opus (2–5 min sin feedback) cuando identidad/placa y FP de bujes ya eran derivables de lo persistido. · **Regla**: `backfillCanonicos` en `montarBloques` — si falta un campo canónico, derivarlo del diagnóstico guardado (`cargarBloques` → `mediciones_raw.unidad`; `derivarBushing(bloques)`) + `actualizarInforme`: instantáneo, sin IA. Antes de re-llamar un servicio caro pregúntate "¿es DERIVABLE de lo ya guardado?"; la IA solo para re-leer la fuente. Toda op larga muestra progreso + fin inequívoco.

### L-44 · Llamada a IA/red = reintento con backoff + presupuesto de tiempo; transitorio se absorbe, permanente se relanza
**Disparador**: toda llamada a IA/red propensa a fallos transitorios. · **Cicatriz** (ADR-015): un 500 puntual de la API de Claude (o que el modelo no llamara la herramienta) surfaceaba como `HttpsError('internal')` sin reintento. · **Regla** (`functions/reintentos.mjs`, puro/testeable): (1) `esErrorTransitorioIA` clasifica por `status` (408/409/425/429/5xx/529), `name` y patrones (`overloaded/ECONNRESET/socket hang up`); permanente (401/400/413) → relanzar ya; (2) backoff exponencial + jitter respetando `Retry-After`; (3) `conReintentosIA(fabricar,{intentos,deadlineMs})` — `fabricar` devuelve promesa NUEVA por intento (un stream consumido no se reusa) y el deadline no inicia intento sin margen; (4) "sin tool_use" se marca 529 (transitorio); (5) cliente Anthropic con `maxRetries:0` (el helper gobierna); (6) presupuestos coherentes cliente↔servidor (`timeoutSeconds` 900 + `httpsCallable` 900000).

### L-45 · Operación larga (IA/red) = trabajo asíncrono OBSERVABLE: el servidor persiste + estado durable; la UI dispara y observa
**Disparador**: cualquier operación de minutos disparada desde la UI. · **Cicatriz** (ADR-016): el reproceso era una llamada bloqueante con un `setInterval` de UI desacoplado del estado real y persistencia en el navegador tras responder → recarga/desconexión perdía el trabajo y el motivo del error moría en un toast. · **Regla**: (1) la Cloud Function PERSISTE ella misma (admin SDK, reusando los MISMOS sanitizadores de dominio sincronizados a `functions/domain` por el predeploy); (2) estado DURABLE en el doc (`reproceso:{estado:'en_curso'|'ok'|'error', inicio|fin, motivo}`) en CADA camino; (3) la UI solo dispara y observa (onSnapshot) — badge que sobrevive recargas + guard de stale (`en_curso` > tope CF → "interrumpido"); botón gateado por estado durable, no por DOM. Helpers puros que el server necesita → a `domain/` con re-export back-compat (`deepClean`, `derivarBushing`).

### L-46 · `await` desnudo sobre un stream de IA = cuelgue invisible e infinito → timeout INTERNO que ABORTA + watchdog (el estado terminal debe estar GARANTIZADO)
**Disparador**: op de red que puede colgarse (stream de IA bajo "overloaded") dentro de una Cloud Function. · **Cicatriz** (ADR-017, 3 intentos fallidos): "⟳ reprocesando…" para siempre — `conReintentosIA` hacía `return await fabricar(i)` SIN timeout por intento (el deadline solo se revisaba en el `catch`, y un cuelgue no "falla") → SIGKILL de plataforma a 900 s → ni `catch` ni `finally` corren → `marcarReproceso('error')` jamás se ejecuta, estado `'en_curso'` eterno. Pista forense: líneas de error VACÍAS en `firebase functions:log` = kill abrupto (OOM/timeout), no excepción. · **Regla**: (1) `conTimeoutAbortable` — AbortController pasado a `client.messages.stream(params,{signal})`, `Promise.race` con timer, y al vencer ABORTA + rechaza `TimeoutIA` (reintentable); (2) presupuesto total < timeout de plataforma (2×400 s + persistencia < 900 s); (3) watchdog global (~870 s) que escribe `'error'` si la función sigue viva; (4) memoria con margen (1→2 GiB: un OOM-kill tampoco corre `catch`). El timeout interno ≥ peor caso legítimo (6.7 min) para no abortar extracciones válidas.

### L-47 · "Claude API: terminated" = bodyTimeout de undici (~5 min) corta el stream largo → extender el bodyTimeout del TRANSPORTE, no el timeout del SDK
**Disparador**: streams de IA largos (>5 min) que mueren con `Claude API: terminated` / 500. · **Cicatriz** (ADR-018): `terminated` es de **undici** (fetch de Node), cuyo `bodyTimeout`/`headersTimeout` por defecto es ~300 s de inactividad; extracción densa (Opus + thinking + `effort:high` + 32k) tarda >5 min → `TypeError: terminated` (cause `UND_ERR_BODY_TIMEOUT`). El `timeout` del SDK Anthropic (10 min) es OTRA capa — no cambia el de undici. · **Regla**: pasar dispatcher sin timeouts: `new Anthropic({ fetchOptions: { dispatcher: new Agent({ bodyTimeout: 0, headersTimeout: 0, keepAliveTimeout: 60000 }) } })` (`undici@^6`); el límite real lo ponen `conTimeoutAbortable` (L-46) + `timeoutSeconds`. Clasificar `terminated`/`UND_ERR_*`/`other side closed`/`premature`/`socket` como TRANSITORIO (mirar `e.cause.code/message`). NO bajar effort/modelo por un problema de transporte; diagnostica por el mensaje de error REAL (consola del navegador), no adivinando.

### L-48 · Reintento bajo presupuesto de tiempo: reserva sitio para un intento ENTERO, no solo el backoff (si no, el último reintento revienta el límite duro → 504)
**Disparador**: reintentar algo CARO bajo un límite duro (Cloud Function `timeoutSeconds`, request deadline). · **Cicatriz** (ADR-019): reproceso EMS denso daba `FirebaseError: deadline-exceeded` + `504` (el error CORS era secundario — un 504 no trae cabeceras CORS). Doble causa: (A) el gate de `conReintentosIA` solo exigía sitio para el backoff (~2 s), no para un intento completo — con `ATTEMPT_MS` 12.7 min arrancaba un 2.º intento que corría hasta los 900 s → SIGKILL → 504; (B) 900 s insuficientes para `effort:high` en escaneo denso (>12–13 min). · **Regla**: el gate de reintento exige `restante > backoff + intentoMaxMs + margen` (patrón "un intento largo + reintento solo si el 1.º falla RÁPIDO"); dimensiona `timeoutSeconds`/timeout cliente/watchdog al PEOR caso real (subido a 1500 s; gen2 admite 3600). Un 504/`deadline-exceeded` casi siempre es "me pasé del límite", no CORS.
